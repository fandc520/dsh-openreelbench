# 工作约定与项目踩坑

本项目特有的规矩和教训。**与 DSH 平台本身有关的坑不在这里**——那些在
`.claude/skills/dsh-plugin-development/SKILL.md` 第 10 节，写插件代码时会自动加载。

分界很简单：

| 问题换个项目还会遇到吗 | 记在哪 |
|---|---|
| 会（任何 DSH 插件都踩） | SKILL.md §10 |
| 不会（ComfyUI / FFmpeg / 本仓库的测试结构 / 工作方法） | 本文件 |

每条按 **症状 → 根因 → 正确做法 → 怎么更早发现** 记。
只写「别这么干」没用——下次踩的时候未必认得出是同一个坑，认得出症状才认得出。

---

## 一、动手前

- **涉及 OM 的结论以实测为准，不转述文档。** 它的 README 描述的能力远超实际可用。
- **不在 `OpenMontage/` 内修改代码。** 需要验证补丁时先说明，改完记录进 DEVELOPMENT.md。
- **不重做 dsh-comfyui 已有的能力。** 工作流管理、参数提取、画布分析、媒体预览都归它。
  参考它的组件是**照着重写**，不是 import（跨插件值导入会破 bundle 纯度门）。
- 分析文档更新后同步 `docs/`，数据变了先跑 `prep.py` 再跑 `inject.py`。

## 二、生成与外部服务

### 2.1 涉及生成的测试必须断言产物互不相同

**症状**：真实 ComfyUI 集成测试 16 项全过，产出全是垃圾——三条配音字节相同、
三张图字节相同。

**根因**：`applyWorkflowParameters` **返回修改后的副本，不改传入对象**
（`lib/params.js` 里 `structuredClone` + `return copy`）。测试丢掉了返回值、
提交了原工作流，于是三次请求完全一致，**ComfyUI 命中缓存返回同一结果**。

**正确做法**：断言 sha256 互不相同，外加「时长是否符合字数」这类量级检查。
一条全绿的管线跑在错误的素材上，比测试失败危险得多。

**怎么更早发现**：凡是「同一个工作流跑 N 次」的测试，第一条断言就是 N 份产物互不相同。

### 2.2 ComfyUI 调度：同类连着跑，不要交替

图像和音频工作流用不同的模型，交替调用会让 ComfyUI 反复卸载/加载模型，
时间几乎全耗在 load models 上。

**所以 assets 拆成 audio / video 两段**：先跑完全部配音，再跑完全部配图。
这不是 UI 分组的需要，是调度约束。

### 2.3 工作流参数以 `comfyui_workflow action: list` 为准

绑定表**只存工作流名称**，不复制参数知识。参数名、默认值、`options` 下拉项
都随用户在面板里的改动实时变，复制一份必然漂移。

绑定用**名称不用 id**：id 是 `randomUUID()`，重新提取一次画布就变，配置会静默失效。

## 三、FFmpeg

### 3.1 concat 要求段编码完全一致

用 concat demuxer 流拷贝拼接前，每段必须归一到同一编码器、尺寸、像素格式、SAR、帧率。
不一致会产生非单调 DTS 和静默损坏的输出——**文件能生成，播放才发现问题**。

### 3.2 zoompan 的 `d` 参数

Ken Burns 要用 `d=1` 配 `-loop 1 -framerate <fps>` 才是逐帧线性推近。
`d=<总帧数>` 会对**每个输入帧**各输出一遍，帧数爆炸。

### 3.3 时间轴以实测为准，不以脚本预估为准

TTS 产出的长度永远不是写脚本时估的。合成前先 ffprobe 量每条配音，
用实测值排时间轴，字幕也按实测走。脚本里的 `start_seconds` / `end_seconds` 是**意图**。

## 四、状态机与校验

### 4.1 校验失败必须真的抛错

**这是整个项目的立身之本。** 做成「提示一下但还是写进去」，整套治理就废了，
插件退化成一组普通工具。

### 4.2 路径穿越要在 schema 层拦

`..` 段和绝对路径都算。不在 schema 层拦，就会以 `ASSET MISSING`
「文件不可读」的名义报出来，把排查方向带偏。

### 4.3 状态机只有一个写入口

面板可以推进状态，但**必须走 `StateMachine.write()`**，不能直接写
`checkpoints/*.json`。走进去，schema / 资产存在性 / 闸 / 前置四类校验一个都不少；
绕过去，四类全失效。

### 4.4 让 Agent 交 schema 化的产物，就要把字段表写进 skill

**症状**：Agent 调 `openreel_stage` 记录 compose，连着两次 `SCHEMA INVALID` ——
第一次多写了顶层字段，第二次 outputs 里少了 `format` / `resolution` / `duration_seconds`。
两次都靠读报错信息试出来。

**根因**：skill 只说了「把 report 原样交上去」，没说这个 report 长什么样。
Agent 读到「原样」，但手里已经有一份自己整理过的摘要，
在它看来把摘要交上去也算「原样」——**「照搬」是个相对说法，相对的是它是否还记得原件**。
在没有字段表的情况下，它只能凭常识拼，而常识拼出来的形状恰好不合法。

**正确做法**：凡是 Agent 要提交、且有 schema 的产物，skill 里必须给**完整字段表**：
哪些必填、哪些选填、顶层和每一项各只认哪几个键。
另外把「原样」写死成不留解释空间的话——「整个对象照搬，一个字段都不要动、不要补、不要重排」。
错误信息能教会它，但那是**用两轮返工换一次学习，而且下个会话又要重学一遍**。

**怎么更早发现**：写完一段 skill，问一句
「照着这段文字，不看源码，能不能拼出一个必定通过校验的对象？」
拼不出来就是缺字段表。

## 五、测试

### 5.1 破坏性测试放最后，并写明原因

路由测试最后会提交 `brief`，**把所有下游阶段作废**。它排在「重写早期阶段」
之前时，那个测试拿到空的 invalidated 数组而失败。

**测试之间的顺序依赖不写在代码注释里，下一个人一定会再踩。**

### 3.7 抄规范里的数字之前，先问它的前提是什么

**症状**：移植字幕排版规范时，「每行 37–42 字」看着像个通用值。
**那是拉丁字母的。** 一个汉字的信息量约等于一个英文单词——
照抄会让中文字幕每行长出一倍半。Netflix 自己的简体中文指引是每行 16 字。

同一份文档里的另一个数字「语速 150–160 wpm」也一样：
我们按 `chars_per_second` 排时间轴，抄 wpm 等于在正确数字旁边放第二个错数字。

**根因**：规范里的数字**都有隐含前提**——语种、画幅、播放场景。
前提和文本一起被省略，抄的时候只看见数字。

**正确做法**：每个要抄的数字问一遍
**「这个值假设了什么？我们这边成立吗？」**，分成三类处理：

| | 例子 | 怎么办 |
|---|---|---|
| 前提成立，直接抄 | 底距 60px、安全区 90%、对比度 4.5:1 | 抄，但按输出画幅缩放 |
| 前提不成立，要换算 | 每行字数（语种）、语速（单位） | 换算，**并在注释里写清原值和为什么不用** |
| 前提不成立，且我们已有 | `chars_per_second` 在 playbook 上 | **不要引入第二个来源** |

**怎么更早发现**：一份规范如果通篇没提语种或画幅，
不代表它是通用的——代表它默认了一种，而那多半不是你这一种。

### 3.6 阈值要跟着风格走，不能是绝对值

**症状**：幻灯片风险里的「每分钟几张画面」用了绝对阈值——6 张以下判「在念幻灯片」。
而 `warm-doc` 的自我描述就是「缓慢、有呼吸感」，`pacing_profile: 'contemplative'`。
**评分在因为一个风格成功地做了它自己而扣它的分。**

**根因**：playbook 存在的意义就是「不同的片子有不同的对」。
任何一个写死的数字都隐含「只有一种对」，直接和 playbook 打架。

**正确做法**：阈值从 playbook 上取。我们已经有 `pacing_profile` /
`maxSectionSeconds` / `kenBurns` 这些字段，它们就是为此存在的。
（`static_hold` 一开始就做对了——它读 `kenBurns` 决定门槛。）

**而且要双向对齐**：技能里告诉模型「该有几张」的那张表，
必须和评分器实际放行的下限一致，否则技能在让模型瞄准一个必被扣分的数字。
写一条测试，在每个 profile 的宣传下限上跑一次，断言得分为 0。

**怎么更早发现**：写下任何一个阈值时问
**「换个风格这个数字还对吗？」**——不对就该从 playbook 取。

### 4.6 要 Agent 确定性地加载某份技能，用 `/name` 手势，别赌它自己认

**背景**：DSH 的技能是渐进披露——常驻上下文的只有目录行
（name + description + whenToUse），正文由模型调 `skill` 工具时才拉。
所以「注册了技能」不等于「模型会用它」，模型得先从目录行认出这事跟它有关。

**做法**：面板发消息时，在文本里放一个 `/skill-name`。宿主的
`SKILL_GESTURE = /(^|\s)\/([a-z0-9]+(?:-[a-z0-9]+)*)(?=\s|$)/g`
会扫描 **user 消息**，命中就把正文注入为指令，位置在所有注入之后、最靠近回答。

前提两条，都已验证：
- `session.prompt()` 产生的消息 source 是 `{ kind: 'user' }`，正是扫描认的那种
- `ctx.skills.register` 默认 `{ modelInvocable: true, userInvocable: true }`

**这既是确定性的，又不是常驻的**——目录一行，正文只在那一轮到场。

**必须写测试**：手势拼错**静默失败**——消息照发，正文永不加载，
模型在没有任何指导的情况下继续干活，看起来一切正常。
从构建产物里查那个字符串在不在，并故意拼错一次确认会 FAIL。

### 4.5 给 Agent 加能力时，先问「它有没有那个入口」

**症状**：给分镜计划加了重复度检查，skill 里写「结果在 `/openreel/state` 的 `variation` 里」。
面板显示正常，测试全绿。**但 Agent 调不了 HTTP 路由**——
对它来说这道检查等于不存在，要一路走到 compose 被拦下才知道出事，
而那时图已经全生成完，正好错过检查存在的意义。

**根因**：面板和 Agent 是**两条独立的通道**。
面板走 HTTP 路由，Agent 只有工具。给面板加的东西默认不在 Agent 视野里，反之亦然。
写 skill 时很容易顺手把「插件内部知道」当成「Agent 知道」。

**正确做法**：能力的**投递时机跟着使用时机走**。
不要让 Agent 去问，而是在它做那件事的那一刻**塞给它**：

- 重复度报告 → `openreel_stage` 提交 `scene_plan` 时**一并返回**
- 自审重点 → `openreel_project action: "status"` 返回**下一段**的，事前不是事后

而且要**渲染进文本**——Agent 读的是 `render()` 的输出，不是 payload。

**怎么更早发现**：skill 里每写一句「结果在 X 里」，
就问**「Agent 用哪个工具能拿到 X？」**——答不上来就是漏洞。

### 5.1b 类型检查用 `npm run typecheck`，不要手敲 `tsc -p tsconfig.json`

**症状**：改了 `src/client/*.tsx`，手敲的 `npx tsc -p tsconfig.json --noEmit` 报 0，
以为没问题；换成 `npm run typecheck` 立刻冒出四个错，其中一个是**用了根本没定义的变量**。

**根因**：`tsconfig.json` 里 `include: ["src/**/*.ts"]` + `exclude: ["src/client"]`——
host 与 client 是**两份 tsconfig**，手敲那条只检查 host。
而 `build:client` 走 tsdown/rolldown，**只转译不检查类型**，
所以构建成功、测试通过、bundle 照常加载，错误一路溜到运行时。

**正确做法**：`npm run typecheck`（它串了 `tsconfig.json` 和 `tsconfig.client.json` 两条）。

**怎么更早发现**：改了 `.tsx` 却只跑了 host 检查——
问一句**「这个文件在哪个 tsconfig 的 include 里？」**

### 5.1c 手写的第三方 API 桩会静默漂移，要照着类型定义抄

**症状**：隔两天回来跑 `pnpm test`，`apply()` 段直接崩：
`settingsCtx.settings.installSection is not a function`。
源码调 `installSection`，测试桩提供的却是 `register`——**桩比真实 API 落后了一整个版本**。

**根因**：桩是照「当时看起来像那么回事」手写的，不是照 `.d.ts` 抄的。
真实 `SettingsProvider` 从来没给消费者暴露过 `register`。
桩和真实实现之间**没有任何东西**把它们绑在一起，所以差异只会在依赖变动
或源码改用新方法时才炸——而那时你已经想不起桩是怎么来的。

**正确做法**：写桩之前先读包里的类型定义，**签名和调用顺序都照抄**：

```js
// 镜像 @deepseek-ai/dsh-settings 的 SettingsProvider.installSection
installSection(owner, ns, schema, entry, hooks) {
  hooks.setSource(() => value)   // 顺序也是抄的：setSource 先于 onChange
  hooks.onChange()
}
```

并在桩旁边写一行注释说明**它镜像的是谁**，下次改依赖时才找得到要同步什么。

**怎么更早发现**：桩里每出现一个方法名，问
**「这个名字我是从 `.d.ts` 里抄的，还是猜的？」**——猜的就去核对。

### 5.6 「产物存在」不是「功能生效」——渲染类测试必须看像素

**症状**：字幕烧录有测试、且长期通过。实际出片里**一个字都没有**。
那条测试烧完一段视频，断言输出文件大小 > 0。
**一个没有可见字幕的视频文件，大小同样大于 0。**

**根因**：断言的是「ffmpeg 没崩」，不是「东西出现了」。
这类测试对整整一类失败完全免疫：滤镜参数写错、字体缺失、
时间戳对不上、图层被覆盖——每一种都产出一个健康的文件。

**正确做法**：**同一帧渲染两次，一次开一次关，逐字节比对**。

```js
const plain = await band('plain.raw', '')                       // 不烧
const burnt = await band('burnt.raw', "subtitles='...',")       // 烧
let drawn = 0
for (let i = 0; i < plain.length; i += 1) if (plain[i] !== burnt[i]) drawn += 1
// 没画：0。画了：几百到几千。
```

比「平均亮度」可靠：文字只占画面 1%，均值只动零点几；
也比阈值法干净：不需要拍一个魔数。

**还要再加一条查「画对没画对」的**。像素比对只能证明「画了东西」——
把 `PlayResX/Y` 删掉（字号放大 3.75 倍那个 bug）后，像素测试**照样通过**，
只是画了更多像素。两条守卫各管一种失败：

| 守卫 | 抓什么 |
|---|---|
| 逐字节比对 | 什么都没画 |
| 断言 ASS 里有 `PlayResX/Y` | 画了，但尺寸全错 |

**怎么更早发现**：任何「生成一个文件」的测试，问一句
**「这个断言在功能完全失效时会不会照样通过？」**——会，就等于没测。

### 5.2 改完源码要 build 再跑测试

`test/smoke.mjs` import 的是 `lib/` 编译产物，不是 `src/`。
只跑 `typecheck`（`--noEmit`）不会更新它，测试跑的还是旧代码。

### 5.5 验证守卫有没有牙，必须在「没有任何回退」的条件下做

**症状**：给提示词引擎写了「每个枚举都必须有短语」的守卫，
故意删掉一条短语验证——**测试照样通过**。

**根因**：那条枚举所在的层还有**另一个字段**由 playbook 默认值填着，
层文本非空，守卫看不出缺口。**默认值把缺失掩盖了。**

**正确做法**：验证守卫时，把所有回退路径关掉再删东西：

```js
// clean-tech 会默认 color_temperature，第 4 层永远非空 —— 换成空默认
const bare = { ...tech, visual: { ...tech.visual, shot_defaults: {} } }
```

**怎么更早发现**：写完守卫**必须故意弄坏一次**，而且要问
**「这条路径上还有谁会替我兜底？」**——有兜底就先拆掉兜底再验。
`5.3` 和 `5.4` 里的守卫都做过这一步，这条是它们的补充：
**光「试过失败」不够，还要确认失败是从你想测的那个原因来的。**

### 5.2b 新能力要在「缺省路径」上验一次，不能只在「已配置」的项目上验

**症状**：五层提示引擎、重复度检查、幻灯片风险三个引擎全部写成
`scenePlan === undefined ? 空 : 算`。开发时用的项目**恰好存过 scene_plan**，
所以一路都正常；换成真实流程——脚本写完直接生图、分镜编辑器一次没开过——
**三个引擎同时静默失效**，发出去的提示词退回裸主体。

**根因**：开发过程中反复手动写过那份数据，于是「有数据」变成了隐形前提。
测试 fixture 也是一路建起来的，同样带着那份数据，**没有任何一条测试跑在缺省状态上**。

**正确做法**：新增依赖某份数据的能力时，**先问「这份数据在正常流程里谁写的」**。
答案是「用户手动操作才有」时，就必须
- 要么让它**可推导**（时间轴 + 脚本已经隐含了分镜计划，那就推导出来）
- 要么接受它默认不生效，并**在 UI 上说清楚**

而且要写一条**把那份数据删掉**的测试：

```js
await fs.rm(join(layout.artifactsDir, 'scene_plan.json'), { force: true })
// 断言功能仍然工作，而不是静默返回空
```

**怎么更早发现**：功能做完问一句
**「一个刚建的新项目，走到这一步时这个功能是开的还是关的？」**

### 5.3b 「按字段白名单合并」的路由，测试必须一次带上全部字段

**症状**：分镜页的 ★高光 开关点了**毫无反应**。前端发了 `hero_moment: true`，
schema 认它，类型检查过，201 项测试全绿——
路由的合并函数字段白名单里**没有它**，静默丢弃，没有任何日志。

**根因**：`mergeSectionShots` 用 `for (const key of ['shot_language', ...])` 逐个搬。
加字段时改了 schema、改了 UI，**忘了改这个白名单**。
而每个已有测试都只发自己关心的那一两个字段，**没有一个测试会发新字段**，
所以漏一个永远测不出来。

**正确做法**：写一个**一次带上全部可选字段**的往返测试，用对象字面量列全，
逐个比对存回来的值；再写一个**逐个清空**的测试——
只能开不能关的控件和不能开一样坏。

```js
const allFields = { prompt, weight, shot_language, texture_keywords, reference_names, hero_moment }
const lost = Object.keys(allFields).filter((k) => JSON.stringify(saved?.[k]) !== JSON.stringify(allFields[k]))
```

**怎么更早发现**：给这类结构加字段时，问
**「从前端到磁盘，这个字段要经过几个显式列举它的地方？」**
本项目是四处：schema 的 `SHOT_KEYS`、路由的合并白名单、client 的类型、UI 的读写。
**漏任何一处都是静默失败。**

### 5.4 同一份清单写在多处时，用测试把它们钉在一起

**症状**：平台名同时存在于 schema 的校验表、渲染的档位表、前端的下拉框。
编译期没有任何东西连着它们，漂移**全部静默**——
下拉框多一个值就是保存 400，少一个值就是选不到，提示文字和实际画幅不符就是界面撒谎。

**根因**：TypeScript 只能保证「这个字符串是这个联合类型」，
保证不了「这三份各自维护的清单内容相同」。

**正确做法**：写一条比对测试，**必要时从构建产物里把前端那份捞出来**：

```js
const bundle = readFileSync('client/client.js', 'utf-8')
const offered = [...bundle.matchAll(/id:\s*"(youtube|douyin|...)"/g)].map((m) => m[1])
```

不只比名字，还要比**语义**：「下拉框承诺的画幅」必须等于「渲染函数算出的画幅」。

**验证测试真的有牙**：故意删掉一项，确认 FAIL，再恢复。
没试过失败的测试不算测试。

**怎么更早发现**：新增一个「可选值列表」时先问
**「这个列表还有第二份拷贝吗？」**——有就当场写比对测试，不要等漂移。

### 5.3 回显类组件要断言「渲染出什么标签」，不是「拿到什么数据」

**症状**：媒体卡片测试全绿，但 `.srt` 在界面上只是一个下载链接，不是预览。
数据层每一项都对——URL 对、kind 对、大小对——**错的是那一个 `kind` 分支挑了 `<a>`**。

**根因**：这类回归**不报错**。链接照样能点，只是不再是预览了，
断言 payload 的测试永远看不见它。数据正确和「人能看见」是两件事，
中间隔着一个分支表，而分支表恰恰是最容易漏一格的地方。

**正确做法**：真调用组件函数，检查吐出来的标签。
`test/render.mjs` 用桩 dispatcher 跑首屏渲染，不需要 `react-dom`
（也**不要**引入——bundle 只允许 import `react`，多一个 React 运行时是净负担）。
断言长这样：

```js
['output/film.mp4', 'video', 'video'],   // 路径 → kind → 必须渲染成的标签
['output/film.srt', 'text',  'pre'],     // 表里出现 'a' 就是失败
```

**怎么更早发现**：凡是「让人看见某个东西」的组件，
问一句**「哪个输入会让它掉进兜底分支？」**，把每个分支都列进表里跑一遍。
兜底分支只该留给真正显示不了的字节。

### 5.7 `.gitignore` 的目录模式必须加前导斜杠，并用测试核对「磁盘上的源码都被跟踪」

**症状**：`git status` 一直干干净净，`src/client/` 整个 UI（24 个文件、约 9800 行）
从来没进过仓库。发现它纯属偶然——提交前顺手看了一眼 `git ls-files`。

**根因**：`.gitignore` 里写的是

```
lib/
client/          ← 想排除的是构建产物目录 client/
```

**不带前导斜杠的目录模式在任意层级都匹配**，所以它同时吃掉了 `src/client/`。

这个坑的恶劣之处在于**它没有任何症状**：
被忽略的文件和「不需要提交的文件」在 `git status` 里长得一模一样，
构建正常、测试正常、类型检查正常，只有仓库是空的。

**正确做法**：

```
/lib/            ← 只匹配仓库根下的这一个
/client/
/tmp/
```

除 `node_modules/` 这类确实想在任意层级排除的，**一律加前导斜杠**。

**用测试钉住**——只核对模式还不够，要核对结果：

```js
const tracked = new Set(execFileSync('git', ['ls-files'], { encoding: 'utf-8' }).split(NL))
// 遍历 src/ test/ docs/，任何 .ts/.tsx/.mjs/.json/.md 不在 tracked 里就失败
```

拿不到 git（发布出去的 tarball）就跳过，别失败。

**怎么更早发现**：加 `.gitignore` 条目时问一句
**「仓库里还有没有同名的子目录？」**；以及首次提交后跑一遍
`git ls-files | wc -l`，和实际文件数对一下。

### 5.8 帧循环测试：时钟要在 `play()` 之前钉住

**症状**：手动驱动 `requestAnimationFrame` 的测试，断言全落空，
数值看着还挺合理，只是不对。

**根因**：播放器在 `play()` 里用当时的时钟算 `origin`
（`origin = now - from`）。测试却在 `play()` **之后**才把假时钟设成目标值，
于是每一帧算出的位置 = 目标 − (旧时钟 − from)，既不是测试想要的、也不是播放器想要的。

**正确做法**：

```js
setClock(FIXED)        // 先钉住
preview.play(position) // origin 在这里算
for (...) { setClock(FIXED); frame() }   // 循环里保持不变
```

时钟保持不变，帧循环才等于「同一个瞬间，反复求值」。

**怎么更早发现**：任何「构造时快照了时间基准」的对象，
测试里设置基准的顺序就是被测语义的一部分，不是准备工作。

### 5.9 「比 X 小」的断言，抓不住方向对但数值全错的实现

**症状**：淡入功能写错了（包络被反馈进压制，电平低了一个数量级），
测试却全绿——因为断言写的是「淡入段的电平 < 中段电平」，
而错误实现**也**比中段低，低得多。

**根因**：只断言**方向**的测试，对「方向对了、数值全错」这一整类 bug 免疫。
而信号处理里绝大多数 bug 正是这一类：反馈、二次施加、单位搞错、
少乘一个系数——它们都不会把大小关系搞反。

**正确做法**：算出**准确的期望值**再断言。

```js
// ✗ if (rising < flat * 0.6)
// ✓ if (Math.abs(rising - bedGain * 0.4) < 0.002)
```

期望值算不出来，说明你还没真正想清楚这一步该做什么——那本身就是信息。

**怎么更早发现**：写下比较符号时问一句
**「有没有一个错误的实现也能满足这个不等式？」**
音频、动画、布局这些连续量，答案几乎总是「有」。

### 5.10 一个东西有自己的变化理由，就该有自己的状态

**症状**：两个独立的调节（压制的逐帧滑动、淡入淡出的包络）都往
`element.volume` 上写，下一帧又从它读回来做增量——**两者互相反馈**，
收敛到谁都没要求的值。

**根因**：把「最终输出」当成了「中间状态」。
`volume` 是两者的**乘积**，从乘积反推任何一个因子都是错的。

**正确做法**：压制电平存自己的字段，包络每帧现算，
`element.volume = 电平 × 包络`。写出去的是结果，读回来的永远是自己的状态。

**怎么更早发现**：一个字段被两处以增量方式修改（`x = f(x)`），
就该拆。判据是**变化的理由**：压制因为有没有人说话而变，
包络因为播放到哪儿而变——两个理由，两份状态。

### 5.11 断言「请求里的值回来了」不等于断言「它起作用了」

**症状**：`openreel_compose` 从来没有 `cut` 参数，剪辑版本每次都被丢掉，
渲染的永远是计划版本——而测试是绿的。

**根因**：断言写的是 `result.cut === cutId`。
这个字段是**从请求里回显的**，剪辑有没有真的进渲染器它都成立。
回显字段证明的只是「我收到了你发的东西」。

**正确做法**：断言**输出的可观测属性**。这里是时长：
剪辑加了 3 秒留白，成片就必须比计划长 3 秒。

```js
// ✗ if (result.cut === cutId)
// ✓ if (edited > planned + 1)
```

**怎么更早发现**：问「如果这个参数在中途被丢掉，这条断言会不会照样通过？」
凡是断言对象来自**入参的拷贝**而不是**产物的测量**，答案就是会。

### 5.12 一个错误码不足以定位守卫

**症状**：删掉「资产阶段必须 completed」的前置检查，测试照样通过。

**根因**：断言只看了 `code === 'PREREQUISITE_VIOLATION'`。
测试项目当时连脚本产物都没有，缺脚本报的是**同一个码**——
挡路的从来不是被测的那个守卫。

**正确做法**：把**其他所有前置条件都满足**，只留下被测的那一个缺着；
并断言错误信息**点名了具体对象**（`assets_audio`），不只是分类。

**怎么更早发现**：一个失败断言要有意义，前提是**在这个场景下只有一条路会失败**。
共享错误码的守卫尤其容易互相顶替。

## 六、工作方法

### 6.1 批量改文件必须先断言锚点存在

**症状**：脚本报告「已更新」，实际什么都没改。连续两次改了个寂寞。

**根因**：Python 普通字符串里的 `\n` 是真换行，而源码文件里是**字面的反斜杠 + n**，
匹配不到。`str.replace` 找不到就静默返回原文。

**正确做法**：

```python
anchor = r"""  console.log('\n== routes ==')"""   # raw string
assert anchor in s, 'anchor missing'              # 先断言
s = s.replace(anchor, new, 1)
assert new in s                                   # 再验证
```

**搜索串和替换串都要用 raw string。** 断言只护住了搜索侧——踩过第三次的形态是
*断言通过、替换也写进去了，但替换内容里的 `\n` 变成了真换行*，把源码写坏。

**怎么更早发现**：任何 `replace` 都配一条 `assert`，两侧都用 raw string，
改完立刻 typecheck。宁可脚本报错，不要「成功」了却改错。

### 6.1b 生成含转义序列的代码，不要用 Python heredoc

**症状。** 用 `python - <<'PYEOF'` 生成 TS/JS 代码，源文件里出现真实换行而不是 `\\n`，
构建报 `Unterminated string literal`。断言锚点存在也拦不住——**坏的是替换内容，不是查找内容**。

**根因。** 反斜杠要穿过 shell heredoc 和 Python 字符串两层，很容易少一层。
`'\\n'` 在普通 Python 字符串里是「反斜杠 + n」，但一旦写成 `'\n'` 就变成换行符，
写进 JS 源码就是把字符串literal 撑断。

**正确做法**，按优先级：

1. **改用 Write / Edit 工具**写这类内容——不经过两层解析，所见即所得
2. 实在要用脚本，用 `chr(92) + 'n'` 拼出反斜杠，**绝不在字符串里手写转义**
3. 能绕开就绕开：`title` 里的换行改成 `·` 间隔号，`join('\\n')` 换成数组直接渲染

**怎么更早发现。** 写完立刻 `npx tsc --noEmit`，不要攒到构建。

**补充（又踩一次，这次踩在查找侧）。** heredoc 把锚点里的转义也吃掉了，
于是 `assert` 直接抛 AssertionError——这是**安全的失败**，什么都没改。
遇到就别修转义了，换个不含反斜杠的锚点：按行号定位，或者拿相邻那一行当锚点。
本轮 `src/tools.ts` 和 `test/smoke.mjs` 都是这么绕过去的。
这个坑本项目踩过五次，每次都是「以为这次写对了」。

**补充二（2026-09-01，这次踩在 heredoc 本身）。** 内容里带成对引号和中文标点时，
`cat > f <<'EOF'` 整个都可能起不来，报 `unexpected EOF while looking for matching '`——
连 Python 都没跑到。同样**不要去修引号**，直接换 Write 工具落文件，
再用 Bash 执行它。生成脚本本来就该是文件，不是 heredoc。

### 6.2 不要在构建进行中重启宿主

**症状**：GUI 启动报
`failed to import loader entry (dsh-openreelbench): bundle script /plugins/.../client.js failed to load`。
而磁盘上文件好好的，`node --check` 通过，测试全绿。

**根因**：宿主在启动时读一次插件产物并挂静态路由。如果那一刻 `client/client.js`
正在被写、或还没写出来，加载失败，**这条路由就再也不会挂上**——进程活着，
但 `/plugins/<插件>/client.js` 一直 404。别的插件正常，只有你的 404。

**怎么确诊**（不要靠猜）：

```bash
curl -sI http://127.0.0.1:3080/plugins/<插件名>/client.js | head -1
```

- **404** → 宿主没挂路由，重启即可，代码没问题
- **200 但浏览器仍报错** → 才是 bundle 本身的问题，去查外部依赖是否都在模块表里

**模块表在哪**：主 app bundle 里那个返回 `{react, "react/jsx-runtime", "react-dom",
"@deepseek-ai/cordis", "@deepseek-ai/dsh-client-ui-slots", ...}` 的函数。
`react/jsx-runtime` **是**提供的，所以 client 可以正常写 JSX。

**正确做法**：`npm run build` 跑完、看到 `Build complete` 再重启宿主。

### 6.3 插件目录迁移要同步四处

`~/.dsh/profiles/<profile>/` 下：`package.json` 依赖、`pnpm-lock.yaml`（两行）、
`node_modules/.package-map.json`（两个值）、`node_modules/<插件名>` 符号链接
（要**原生**符号链接：`MSYS=winsymlinks:nativestrict ln -s`）。

漏一处 DSH 就加载不到，而且不一定报错。

### 6.5 第三方 skill 的模板不是格式真相，先验一份最小产物

**症状。** 装了 `excalidraw-diagram-generator`，照它 `templates/*.excalidraw` 的写法
把文字当属性挂在图形上（`{"type":"rectangle","text":"立项"}`），
生成的图在 Excalidraw 里打开是**一堆空白方框**——JSON 完全合法，就是不显示字。

**根因。** Excalidraw 的真格式是**独立 text 元素 + 双向绑定**：容器的 `boundElements`
指向 text，text 的 `containerId` 指回容器。`rectangle.text` 这个字段根本不存在，被静默忽略。
该 skill 的 `references/excalidraw-schema.md` 里没有 `containerId` 一词，
还写着「`boundElements` 通常保持 `null`」——**它的参考文档本身就是错的**，
照着写不会报错，只会安静地少东西。

**正确做法。**

1. 用第三方 skill 生成**目标程序才能验证的格式**（.excalidraw / .drawio / .docx / .pptx）时，
   先出一份三五个元素的最小产物，在目标程序里打开确认，再放量
2. 别把 skill 的 `references/` 当规范——它是作者的笔记，不是上游文档。
   有疑问以目标程序的实际行为为准
3. 本项目已有可用的生成器与校验器，别重造：
   `docs/diagrams/gen-pipeline.py` 的写法（`shape` / `label` / `ftext` / `arrow` 四个函数）
   产出的就是真格式，箭头还绑定到两端图形，拖动时会跟着走

**怎么更早发现。** 写个结构校验脚本，别只 `json.load` 就算过。至少查五件事：
id 唯一、所有 `boundElements`/`containerId`/`startBinding`/`endBinding` 能解析、
`index` 字典序递增（用 `format(i,"x")` 会让 `a10` 排在 `a9` 前面）、
绑定文字宽高不超出容器、实心元素两两不重叠。
本项目的 `docs/diagrams/check.py` 就是这个，86 元素的图跑一次不到一秒：

```bash
python docs/diagrams/gen-pipeline.py            # 重新生成
python docs/diagrams/check.py docs/diagrams/pipeline-comfyui-boundary.excalidraw
```

**症状。** 按用户口述画了「构思→分镜→生成→合成」四段状态机，
实际 `src/pipelines.ts` 里是 **brief → script → assets_audio → assets_shots → compose 五段**，
`GATED_STAGES` 是**四道闸**不是两道。图好看，但是错的，而且错得不显眼。

## 七、客户端样式表

### 7.1 样式表里出现反引号，会终止它自己的模板字符串

**症状**：改完样式跑 `npm test`，**一条测试都没跑**，输出是 rolldown 的解析错误，
箭头指着 CSS 注释里的一句散文，还建议你「Try inserting a semicolon here」：

```
╭─[ src/client/workbench-styles.ts:789:24 ]
│ 789 │    Its own class, NOT orb-btn-accent: that name means "ask the model again"
│      │                        ╰─
│ Help: Try inserting a semicolon here
```

**根因**：`const CSS = ` 后面整段是一个模板字符串。里面任何一个反引号都会**提前闭合**它，
后面的 CSS 就被当成 TypeScript 源码解析——于是报错指向的是「散文」，不是「字符串坏了」。

**正确做法**：CSS 里**一个反引号都不能有**，注释里也不行。要引用类名就直接写
`.orb-btn-accent` 这个名字，不要给它加引号包裹。

**怎么更早发现**：认症状。**「rolldown 指着一句中文/英文散文说缺分号」= 样式表里混进了反引号。**
文件头部注释里的反引号是安全的（在字符串外面），只有 `const CSS = ` 之后的算。

不需要为它写测试——**构建本身就是检测器**，而且一定先于测试触发。
写过一条断言，结果它永远跑不到：能让它失败的文件同样会让构建失败。
这里缺的从来不是检测，是**认出这个报错长什么样**。

### 7.2 同名 class 声明两次，后面那条赢，而且看起来像是设计如此

**症状**：新写的样式「没生效」，但元素确实带着那个 class，DevTools 里也能看到规则——
只是被同名的另一条覆盖了。

已经发生两次：
- `.orb-select-small` 隔着 594 行声明两次 → 镜头语言下拉框比设计宽，用户反馈「太挤」
- `.orb-btn-accent` 隔着 486 行声明两次（一条是强调色，一条是「未保存」的金色）
  → 四个界面上六个「重新生成」按钮**全部渲染成金色**

**根因**：两处各自都读得通，谁也不知道对方存在。而**颜色错了仍然像是有意为之**，
所以没有任何一个环节会觉得不对。

**正确做法**：一个 class 一个含义。含义变窄的那个改名（上例里「未保存」改成
`.orb-btn-dirty`，因为它只有一个使用点）。

**怎么更早发现**：冒烟测试里有一条 `class name collision`，直接扫样式表里重复的选择器。
新增样式时它会告诉你撞了谁、在哪两行。

### 7.3 抄一个相似结构时，连它的前提一起抄

**症状**：新加的轨道块跑到了时间轴最上方，压在刻度尺上，而不是待在自己那条轨里。

**根因**：`.orb-music-block` 照着字幕条写了 `position: absolute`，
但 `.orb-lane-blocks` 是**没有定位的 flex 行**，绝对定位的子元素于是向上
找到最近的已定位祖先，落在轨道顶端。

字幕条能这么写，是因为字幕轨自己额外加了 `.orb-lane-cues { position: relative }`——
它必须绝对定位，因为每条字幕各有各的偏移。**这个前提没被一起抄过来。**

**正确做法**：先问「我这个块需要各自偏移吗」。不需要（只有一块、铺满整条轨）
就用普通流式布局，`flex: 1 1 auto; width: 100%`。

**怎么更早发现**：写下 `position: absolute` 时，**当场找出它的定位祖先是谁**。
找不到，就是要么加 `position: relative`，要么不该用绝对定位。

## 八、音频

### 8.1 `loudnorm` 单遍是动态的，会抵消掉你刚做好的动态处理

**症状**：侧链压制在中间产物里量得好好的，混进成片就没了——
或者变浅一半。没有报错，输出里也没有任何东西可指。

**根因**：ffmpeg 的 `loudnorm` 在**没有测量值**时默认动态模式，随时间调增益。
它把句子之间的空隙听成「太安静」，于是把音乐顶回空隙里，
一段一段抵消刚做好的 ducking。

**正确做法**：两遍。

```
1) ffmpeg -i mix.wav -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -
2) 从 stderr 末尾取最后一个 {...}，把 measured_* 和 offset 填回去，加 linear=true
```

`linear=true` 施加**一个固定增益**，动态原封不动。代价是音频多解码一遍。

**测量失败时退到 `alimiter` 峰值限制，不要退回动态 `loudnorm`。**
把失败的测量变成一个静默错误的混音，比差几个分贝糟得多。

**怎么更早发现**：凡是「先做动态处理、再做整体归一化」的链路，
问一句**「归一化那一步是静态的还是动态的？」**

### 8.2 压缩器的增益衰减要实测，教科书公式对 ffmpeg 的软拐点不成立

**症状**：按 `GR = 超阈值量 × (1 − 1/ratio)` 算出 9 dB，实测 3–7 dB。
更迷惑的是**加大 ratio 几乎没有反应**（3→20 只从 3.4 变到 4.5 dB），
看起来像参数没生效。

**根因**：两件事叠在一起。

1. `sidechaincompress` 是**软拐点 + RMS 检测**，教科书公式假设硬拐点 + 峰值检测
2. 当时的**测量方法**用单个 `bandpass` 隔离频段，2 阶滤波器对 600 Hz 外的
   干扰音抑制不够，泄漏抬高了本底，把一半效果盖住了

第 2 条是「改 ratio 没反应」的真正原因——被盖住的部分不随 ratio 变。

**正确做法**：

- 用**两个相距足够远的正弦**做被测信号与 key，测量时用**级联**滤波器
  （`highpass×3 + lowpass×2`），不要用单个 `bandpass`
- 把实测值写进代码注释，并注明它和算出来的不一样
- 让测试**每次重跑这个测量**，断言落在规范区间内而不是等于某个数

**怎么更早发现**：测量工具不够陡的时候，症状是
**「这个参数好像没用」，不是「测量不准」**。
参数扫描出现「饱和」而理论上不该饱和，先怀疑测量。

### 8.3 lavfi 的 `sine` 输出是 −18 dBFS，不是满量程

**症状**：拿 `sine` 造的 key 去触发侧链压缩，一点动静都没有。

**根因**：`sine=frequency=200:duration=10` 出来峰值约 −18 dBFS。
再叠一个 `volume=-6dB` 就到 −24 了，远低于 0.05（≈ −26 dB）的阈值线附近，
压缩器根本不工作——看起来像滤波器写错了。

**正确做法**：造音频夹具时**先量一遍**（`-af volumedetect`），
按目标电平补增益。真实解说峰值在 −12 ~ −15 dBFS，夹具就照这个来。

**怎么更早发现**：任何带阈值的处理，先确认**输入真的过了阈值**再怀疑处理本身。

### 8.4 面板给方向，措辞按模型规范转写

**面板不知道绑定后面是哪个模型。** 同一个意思，SDXL 要逗号分隔的标签、
Flux 要一句自然语言、音乐模型两者都不要。在插件里写死一份措辞，
换个模型就**不报错地生成得不对**。

分工是：

| | 谁定 |
|---|---|
| **内容 / 方向**——拍什么、多快、什么调性、哪五层 | 插件与面板 |
| **措辞**——写成什么形状喂给这个模型 | Agent，按工作流自己的技能包 |

`dsh-comfyui` 已经有这个机制：`comfyui_workflow` 的 `action: "skill"`
返回该工作流的技能包，而用户标了 `requireSkill` 的工作流**不读就拒绝运行**。

**所以每一处会写提示词的技能都要指向它**——不是只在管线地图里说一次。
面板请求只加载那一份阶段细则，地图不在上下文里。

**这条不等于放开重新拼模板。** 五层提示词存在的理由是固定前后缀曾占掉 84% 的词、
十段出十张同款。转写的是**措辞**，不是**内容**：不许删层、不许加回风格前后缀。
两句话要写在同一处，否则细则自相矛盾。

## 九、人机同步：哪一步交给 Agent，哪一步直接执行

### 9.1 判据

**每一个"提交按钮"都要先回答一个问题：下一步需要 Agent 判断或生成吗？**

| 下一步是什么 | 怎么做 |
|---|---|
| **要生成内容**（脚本、配音、图像、配乐） | 交给 Agent |
| **要做创作判断**（选风格、定镜头语言、选曲） | 交给 Agent，并用 `/skill` 手势带上对应技能 |
| **只是执行页面上已经定好的决策**（合成、保存、裁剪、排序、过闸） | **宿主直接做** |

判据不是"这一步重不重要"，而是**"模型在这里还剩什么可决定的"**。
合成是最好的例子：剪辑版本、停顿、字幕样式、配乐全在页面上定完了，
把它们编成一段话交给模型，只是多一次往返、多一个转述出错的机会——
而且真的出过错（`cut` 参数不存在，剪辑版本每次被静默丢掉）。

### 9.2 但直接执行的那条路，**必须同时给 Agent 留通路**

这是这条规则的另一半，也是更容易烂掉的一半：

> **全自动流程没有按钮可按。**
> 面板能做的每一件推进管线的事，Agent 必须也能通过工具做到。

做法是**两条路径调同一个函数**，不是各写一份：

```
面板按钮 ──┐
           ├─→ composeProject() ─→ renderProject()
工具调用 ──┘
```

各写一份的后果是治理**在一条路上成立、在另一条路上被绕过**——
前置检查、幻灯片拦截、画幅解析，任何一条漏了都不会报错，只会悄悄出片。

冒烟测试里有一张表钉住这个对应关系，新增直接执行的动作时**同时加一行**。

**那张表要读 action 枚举，不能搜 schema 的文本。** 第一版是把
`JSON.stringify(tool.parameters)` 拿去搜动作名——结果它搜到的是
`path` / `start` 这些参数**描述里提到的** `trim_audio`，
于是把动作从枚举里删掉，测试照样全绿。

> 它断言的是「schema 里提到了这个词」，而我要的是「模型调得到这个动作」。

正确写法：

```js
const actionsOf = (tool) => allTools.get(tool)?.parameters?.properties?.action?.enum ?? []
const paramsOf  = (tool) => Object.keys(allTools.get(tool)?.parameters?.properties ?? {})
```

没有 action 枚举的工具（如 `openreel_compose`）则断言**参数存在**。

### 9.4 什么**不需要**给 Agent 通路

判据是**这一步的决定权在谁手上**，不是「面板上有没有这个控件」：

| 面板上的东西 | 要不要工具 | 为什么 |
|---|---|---|
| 参考图 / LoRA 名 | **不要** | 这是人**提供的输入**，不是管线做的决定。Agent 只需要**读**（`status` 返回整个 marker），不需要写 |
| 配乐的音量 / 淡入淡出 | **不要** | 默认值就是规范值（W3C 的 −20dB 等）。技能里明确写了电平不归模型管——再给一个工具等于把刚拿掉的旋钮装回去 |
| 配乐工作流名 | **不要** | 那只是面板替用户记着上次填的；Agent 自己跑 ComfyUI 时本来就要选工作流 |

> **人提供的输入 ≠ 管线做的决定。** 前者只需要能读，后者才需要能写。
