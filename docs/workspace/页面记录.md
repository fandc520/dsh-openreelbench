六个页面的推导
页面 0 · 欢迎页
何时显示	会话里还没有项目时
内容	输入框「你想做一条什么片子？」+ 管线卡片 + 最近项目列表
数据源	GET /openreel/library（项目列表）· 管线定义（不存在）
主动作	conversation.send(输入内容) → Agent 判断管线 → 调 init
缺	① 管线定义
「变相的管线选择」这个设计是对的：用户说需求，Agent 选管线。管线卡片只是让用户知道现在有哪些能力，不是让他填表。

页面 1 · 项目详情（brief 闸）
数据源	state.project · state.style.playbook · state.artifacts.brief
组件	表单 + 风格卡（调色板 / 提示词模板 / 一致性锚点预览）
可编辑	标题 · 目标时长 · 风格 · brief 的 hook / key_points / audience / tone
提交	stage:'brief' + human_approved:true，然后 send 一句「简报已通过」
缺	② 风格列表没进 state ③ 改标题/时长/风格没有路由

页面 2 · 脚本（script 闸）
数据源	state.artifacts.script · state.style.playbook（校验阈值）
组件	表格：# / 时长 / 标签 / 正文 / 配图提示词 / 表演指导
可编辑	每段正文、visual.prompt、delivery_cues；增删段、重排
校验标记	段时长超 maxSectionSeconds · 字数超预算 · 段间重叠 · 缺 delivery_cues
缺	④ 实时校验接口
这里有个设计陷阱要避开：校验规则不能在前端重写一遍。它们在 schema.ts + playbook 里，前端复制一份必然漂移（这正是绑定表不复制参数知识的同一个理由）。
需要 POST /openreel/validate —— 跑同一套校验器，返回问题清单，不落盘。POST /openreel/stage 也校验，但它会写。

页面 3 · assets-audio（闸）
数据源	state.artifacts.script（要念什么）· asset_manifest_audio（含 url）· project.voice · bindings.tts
组件	音色选择器 + 样音播放 + 逐段配音列表（播放器 + 实测时长 vs 脚本预估对比）
生成动作	全部 send：「生成样音」「批量配音」「重录第 3 段」
提交	stage:'assets_audio' —— 样音 + 全部配音一次通过
缺	⑤ set_voice 没有路由（工具有） ⑥ 音色候选拿不到
⑥ 是设计问题不是接口问题：候选音色是 ComfyUI 工作流参数的 options，openreelbench 查不到。

我的方案：项目上存一份候选快照，Agent 查完写进去；面板从 state 读并渲染选择器，旁边给「刷新」按钮（= send）。快照会过期，但比没有强，且过期是可见的。这条要你拍板，因为它给 marker 加字段。

页面 4 · assets-video（闸）
结构同页面 3，组件换成配图网格（缩略图 + 提示词 + 单张重做）。风格微调按钮 = send。

缺：无新增（复用 ⑤ 的模式）。

页面 5 · 时间线（compose）
数据源	render_report · 两个 manifest · state.film.url
组件	时间轴（段块 + 音频轨 + 字幕轨）+ 播放器
动作	「合成」= send（合成要几分钟，HTTP 请求会挂，必须交给 Agent）
缺	⑦ render_report 不带 timeline，时间轴画不出来
后端缺口汇总（7 项）
#	缺口	挡住哪页	规模
①	管线定义（Pipeline.stages[].screen）	0 + 界面路由	中
②	风格列表进 /openreel/state	1	小
③	改标题/时长/风格的路由	1	小
④	POST /openreel/validate	2·3·4	中
⑤	set_voice 路由	3	小
⑥	音色候选快照（要你拍板）	3	小
⑦	render_report 带上 timeline	5	小
③⑤ 可以合并成一条 POST /openreel/project（改 marker 上的可变字段），比开五个路由干净。

建议的推进顺序
你说要一个一个检测落实，那按「每步都能看见东西」排：


第 1 步  后端补口：① 管线定义 + ②③⑤⑦（②③⑤⑦ 都是小改）
第 2 步  面板骨架 + 欢迎页 + 管线轨    ← 第一次看见界面
第 3 步  工作室看板容器 + 资产库        ← 你能浏览产出物了
第 4 步  页面 1 项目详情
第 5 步  ④ validate 路由 + 页面 2 脚本表格   ← 最有价值的一页
第 6 步  页面 3 audio
第 7 步  页面 4 video
第 8 步  页面 5 时间线
把资产库提到第 3 步，是因为它不依赖任何缺口（/openreel/library 已就绪），做完你立刻有实用价值，而且能验证媒体路由在真实浏览器里工作正常——这是后面所有页面的地基。

开始前要你定两件：

⑥ 音色候选快照 —— 同意在项目上存一份 Agent 写入的候选列表吗？还是面板只显示当前音色 + 「换音色」按钮走对话？
第 1 步的范围 —— ①②③⑤⑦ 一起做（约 150 行），还是先只做 ① 管线定义，让骨架能跑起来再补其余？
